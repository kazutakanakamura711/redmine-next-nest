# 今後の実装メモ

Figma の確認で決まった表示方針と、初期実装では後回しにする内容を記録します。正式な画面・API 仕様は [UI_API.md](./UI_API.md)、データルールは [DOMAIN_MODEL.md](./DOMAIN_MODEL.md) を参照します。

## プロジェクト一覧の方針

- アクティブなプロジェクトとアーカイブ済みのプロジェクトを、どちらも一覧に表示する。
- API の取得順は `createdAt` の降順（新しいプロジェクトが先）とする。
- アーカイブ済みのプロジェクトは削除せず、`isArchived` を使って状態を表す。

## 画面表示の方針

### プロジェクト一覧

- アーカイブ済みの行も表示する。
- アーカイブ済みの行は通常の行より薄く表示し、状態が分かるようにする。
- 状態列にはアーカイブ済みであることを表示する。

### サイドメニュー

- アーカイブ済みのプロジェクトも表示する。
- アーカイブ済みのプロジェクトは薄く表示し、アーカイブ状態を表すアイコンを付ける。

## 別タスク: プロジェクトのアーカイブ解除

アーカイブ済みプロジェクトを再び利用可能にする API と UI は、[プロジェクトのアーカイブ解除タスク](./PROJECT_ARCHIVE_RESTORE_TASK.md)で実装する。

## 後回し: サイドバーからのアーカイブ操作

プロジェクト設定画面などの基本機能を一通り揃えた後、サイドバーの操作メニューからプロジェクトをアーカイブ・解除できる機能を別タスクとして検討する。

## 初期実装では後回しにする内容

- ページネーション
- プロジェクトの検索
- プロジェクト一覧の絞り込み

これらを実装する際は、画面だけでなく `GET /api/projects` のクエリパラメータ、レスポンス形式、API テストも合わせて設計する。

## プロジェクト一覧 API を実装するときの確認項目

- アーカイブ済みを含めて取得できること。
- `createdAt` の降順で返ること。
- アクティブ・アーカイブ済みの両方を含むケースを E2E テストで確認すること。
- 一覧画面でローディング・空・エラーの状態を扱うこと。

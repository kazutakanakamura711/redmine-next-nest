# タスク: プロジェクトのアーカイブ解除

## 背景

プロジェクトのアーカイブは `isArchived: true` にする論理操作であり、既存データは保持される。現在はアーカイブ解除の API と UI がないため、一度アーカイブするとアプリから通常の利用状態へ戻せない。

アーカイブ済みプロジェクトは引き続き一覧・サイドバーに表示し、タスクを閲覧できる方針とする。アーカイブ解除後は、タスクの作成・更新を再び可能にする。

## 目的

アーカイブ済みプロジェクトを、データを削除せずにアクティブ状態へ戻せるようにする。

## 作業範囲

### API

- `POST /api/projects/:projectId/archive` で `isArchived` を `true` にする。
- `POST /api/projects/:projectId/unarchive` で `isArchived` を `false` に戻す。
- どちらもリクエスト本文は不要とし、成功時は更新後の Project を `200` で返す。
- 存在しないプロジェクト ID は `404` を返す。
- アーカイブ解除では Project や関連データを物理削除しない。
- API の成功・404・状態変更を E2E テストで確認する。

### プロジェクト設定画面

- アクティブなプロジェクトでは、現在の「プロジェクトをアーカイブ」Danger Zone を表示する。
- アーカイブ済みプロジェクトではDanger Zoneを隠し、「アーカイブを解除」操作を表示する。
- 成功後はトーストを表示し、最新のプロジェクト状態を画面へ反映する。

## 受け入れ条件

- アーカイブ済みプロジェクトをアプリからアーカイブ解除できる。
- 解除後、`isArchived` が `false` になり、詳細・サイドバー・一覧にアクティブ状態が表示される。
- アーカイブ解除後はタスクの作成・更新が可能な状態になる。
- 存在しないプロジェクト ID を指定した場合、API が `404` を返す。
- 既存のプロジェクトや関連データが失われない。
- API、UI、テスト、Swagger、関連ドキュメントの変更が揃っている。

## 対象外

- プロジェクトやタスクの物理削除（`DELETE /api/projects/:projectId` は将来対応）
- プロジェクトキーの変更
- サイドバーの操作メニューからアーカイブ・アーカイブ解除する機能（別タスクで対応）
- 認証・owner 権限の実装（認証導入時に、アーカイブ解除を許可する role も API 側で検証する）

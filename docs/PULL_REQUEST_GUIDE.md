# Pull Request の作成・確認手順

このドキュメントでは、このリポジトリで Pull Request（PR）を作成するときの基本ルールをまとめる。

## PR 作成前

1. 変更内容に合ったテスト、lint、typecheck などを実行する。
2. PR の「確認」には、実際に実行したコマンドと手動確認だけを書く。実行していない項目を完了扱いにしない。
3. 変更を commit し、作業ブランチを `origin` に push する。
4. フロントエンドの変更がある場合は、ブラウザで画面を確認し、変更後のスクリーンショットを用意する。

## PR の設定

- base（マージ先）は `develop`。
- assignee は `kazutakanakamura711`。
- タイトルは変更の種類と内容がわかるようにする。例: `feat: add project unarchive flow`、`fix: show project update errors in Japanese`。
- PR 本文は GitHub が読み込む `.github/pull_request_template.md` の見出しを使う。

## PR 本文の項目

- **概要**: 何のための変更かを短く説明する。
- **実装内容**: 主な変更を箇条書きにする。
- **確認**: 実行したコマンドと、必要な手動確認を書く。
- **補足**: 既知の制約、後続タスク、レビュー時に知っておくことを書く。なければ「なし」とする。
- **画面確認**: フロントエンドに変更がある場合は、変更後のスクリーンショットを貼る。バックエンドのみなど画面に影響しない変更は「該当なし」とする。

## スクリーンショットの貼り方

1. PR の説明文を編集し、「画面確認」欄にカーソルを置く。
2. スクリーンショットを本文エディターに貼り付けるか、ドラッグ＆ドロップする。
3. GitHub が画像をアップロードし、Markdown の画像リンクを挿入したことを確認する。
4. 画像が PR 本文に表示されることを確認してから保存する。

スクリーンショットは変更後の画面が分かる範囲で撮影し、通常はリポジトリに画像ファイルとして commit せず、PR 本文に添付する。画面確認が不要な変更では画像を用意せず、「該当なし」と記載する。

## 作成後

- PR の base、assignee、タイトル、本文が正しいことを確認する。
- CI の結果を確認する。
- フロントエンドに変更がある場合は、PR 本文上でスクリーンショットが正しく表示されることを確認する。
